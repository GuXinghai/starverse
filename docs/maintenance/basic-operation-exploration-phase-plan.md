## 目标与探索方式

从普通用户的基础操作出发，检查操作能否完成、界面和持久化状态是否一致、
取消或失败后能否继续使用，以及反馈是否足以让用户理解当前状态。

任务目标和覆盖范围固定，具体操作路径由 Agent 根据实时界面反馈决定。
通过界面完成操作，不使用直接写数据库、内部 IPC 或 fixture 权限替代被测流程。
发现异常后记录现场并做最小复现；代码修复单独安排、单独提交。

## 数据与运行范围

- 复用已有 Electron 与 Playwright，不安装新软件、浏览器或 MCP。
- 使用独立且可重复使用的 `basic-exploration` profile，保留跨运行的测试数据。
- 测试 profile 位于 `%USERPROFILE%/.starverse-agent/profiles/basic-exploration/`，
  不复制日常使用的 profile，不读取或迁入其凭据。
- 每次执行前记录已有测试对象；操作对象使用可识别的阶段前缀，删除仅针对
  明确登记的可丢弃对象，不自动清空整个 profile。
- 网络沿用应用正常行为。A 段不主动发送模型请求，不等于强制断网；
  正常后台目录或云规则刷新应与用户主动操作分开记录。
- 默认通过隐藏窗口和离屏绘制探索。截图及 DOM 观察不构成原生窗口、
  系统焦点、输入法或 DPI 行为的验收。
- 原始截图、日志、测试数据库继续保留在仓库外；仓库内文档记录证据位置、
  复现步骤和结论，不提交凭据、原生二进制或大体积运行产物。

## A 段：无需真实生成历史的基础操作

A 段是首次执行范围。尚无正式会话的数据不能记为正式会话功能已覆盖。

| 范围 | 自主探索任务 | 观察与核对点 |
| --- | --- | --- |
| 初始状态与导航 | 查看空状态；开关设置和搜索；显示、隐藏整个项目区域 | 提示、按钮状态、当前选中项与返回路径是否一致 |
| 项目管理 | 新建两个项目；重命名；取消操作；删除空项目 | 列表与选中状态是否更新；空名称、重名及取消反馈是否清楚 |
| 模板草稿 | 输入中文、英文、特殊字符及多行内容；修改、全选删除；离开后返回 | 输入与换行行为、草稿归属及保留/清空是否符合当前约定 |
| 基础搜索 | 搜索项目名；切换匹配方式；查询无结果；清空查询 | 结果准确性、项目定位、空状态及关闭后的恢复 |
| 普通设置 | 语言、当前存在的普通开关及启动选项；保存后重新打开 | 界面显示与保存值一致；关闭和取消行为清楚 |
| 重启恢复 | 使用同一 profile 重启；对照当前启动选项回看项目、设置和模板草稿 | 分别记录动作后、切换后、重启后观察，不凭当时界面变化认定持久化通过 |

每类任务可增加少量自然变化，例如空输入、取消、重复操作、切走再返回。
不将本轮扩展为大规模输入模糊测试、并发或长时间压力测试。

## B 段：基础文字对话与正式会话管理

B 段待确定一个测试 Provider、一个文本模型及可接受的请求范围后安排。
本次计划提交不读取或配置 API 密钥，不发送任何模型请求。

先通过真实界面建立少量正式会话，再覆盖：

1. 首次发送、连续追问、流式回复、停止生成，以及失败提示和恢复。
2. 正式会话重命名、切换、移动项目、单条和批量选择、取消及确认删除。
3. 跨正式会话草稿隔离，以及切换或按约定重启后的恢复。
4. 会话标题、用户正文、助手正文搜索，结果定位及命中导航。
5. 非空项目删除后的会话归属、列表和计数变化。

分别记录“发送已被接受”“正式会话已出现”“模型回复成功”，不把三者合并
为同一个成功状态。回复失败时，也应按实际已提交的状态检查会话和历史。

## 基线实现中的预期边界

以下语义来自基线实现，执行时若实现或产品约定变化，应先更新预期：

- “新建”打开已持久化但在正式列表中隐藏的系统新对话模板，并非立即新增
  一条正式会话。首次 accepted initial-send 事务会将其提升为正式会话并创建
  后续模板，无需等待模型成功回复。
- 新建操作可能切换到模板所属项目，不能假定它总属于点击前选中的项目。
- 默认启动选项可能清空模板草稿；应对照启动重置选项判断，不统一要求
  所有草稿重启后保留。正式会话草稿和模板草稿应分别观察。
- 删除项目会将其会话移入收件箱，不应把保留会话判为删除失败。
- 项目区域显示/隐藏不是每个项目树节点的折叠功能，也未在本计划中要求
  该局部显示状态跨重启保存。
- 批量全选针对当前加载的列表，不自动视为覆盖尚未加载的全部分页。
- 项目/会话管理使用 DOM 模态；本地文件选择使用原生 Electron 对话框。

关键实现位置：

- `src/ui-app/app/appChatApp.logic.ts`：模板激活、会话管理、草稿切换与搜索定位。
- `infra/db/repo/systemChatTemplateV2Repo.ts`：模板提升与启动草稿重置。
- `infra/db/repo/conversationWorkspaceV2Repo.ts`：项目删除后的收件箱归属。
- `src/ui-app/components/NewChatLifecycleSettingsPanel.vue`：启动与新对话选项。

## 结果记录与完成标准

每个任务使用以下状态之一：已验证、可复现问题、预期待确认、受限或未覆盖。
没有执行、缺少数据或条件不足的任务不得记为通过。

每个问题至少记录测试对象、最短复现步骤、预期与实际结果、影响范围和严重度、截图/快照/日志
位置、是否可恢复，以及必要的发生次数。保留首次失败证据，复现后避免重复
刷同一路径；发生持续崩溃、无法继续观察或控制接口无法完成的原生交互时，
停止该路径并记录限制，不以重置数据掩盖问题。

A、B 两段分别汇总覆盖情况、发现的问题、未覆盖项和待确认决策。
阶段收尾需要形成这些记录及修复/延期安排；完成一次探索不自动等于缺陷
全部修复，也不构成发布验收。

后续提交按用途区分：阶段计划、探索记录与问题清单、单个已确认问题的修复
及针对性验证。本次提交只包含阶段计划，不提前生成测试结果或完成声明。
